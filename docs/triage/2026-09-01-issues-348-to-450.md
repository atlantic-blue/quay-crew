# Twenty open issues read against main, 1 September 2026

Twenty issues were read against the code on `main` at `d508eec`. The question for each one was not
whether somebody worked on it. It was whether the behaviour the issue asks for is in `main` today.

Four of the twenty were closed. Sixteen stay open.

## How each one was read

Each issue was read whole, with its acceptance criteria. Then the code, the tests and the scenarios
on `main` were searched for the behaviour. A commit subject and an issue reference were treated as a
claim, not as evidence. Only two of the twenty carry a merged commit that names them, and one of
those two is still open.

Where an issue names a command, the command was run. The tool was built from `d508eec` with
`go build -o /tmp/krewe ./cmd/krewe`.

The suites were run at that commit. `go test -count=1 ./features/` reports 996 scenarios, 987
passed and 9 failed. All nine failures are the install scenarios, which call `make`, and this
sandbox holds no `make`. `go test -count=1 ./internal/controlplane/... ./cmd/krewe/...` is green
after the hooks are built, which the deploy identity tests need.

Nobody drove a live control plane, so no criterion that needs a model, a token or a running system
was settled by observation. Where that limited an answer, the line below says so.

## Closed

Each line names what proves the behaviour is on `main`.

**400, the control plane serves reads and dispatches nothing.** `internal/controlplane/dispatchwaits.go`
names each wait, gives the whole start path one 60 second budget, and gives the event log export 5
seconds. The export was the wait: a producer that accepted a connection and answered nothing held
the record without limit.

`Dispatch` writes a log line before it does anything, at
`internal/controlplane/server.go:1274`. The scenario is "A dispatch that cannot start says what it
waited for" in `features/dispatching.feature`. The health check writes where a dispatch writes:
`internal/store/migrations/0027_health_probe.up.sql` and `features/health.feature`. The side finding
is fixed too, in `cmd/krewe/scope_test.go`, `TestTheWideningAdviceIsTypeable`.

**405, the system reports its own headroom.** `internal/headroom` reads the daemon on a timer of its
own, and every figure is measured or reads unknown. `features/headroom.feature` holds ten scenarios,
including the header word, the machine underneath reported apart from the daemon, and the sandbox
listing sorted by memory. The header reads the last sample through `console.RoomFrom`. The view is
`internal/console/roomsummary.go`. `krewe room` answers from the system where there is no sandbox
accounting to read, at `cmd/krewe/room.go`.

**419, a refusal exits 0.** `krewe task --detach <address> "some text"` prints the refusal and exits
1, run against the binary built from `d508eec`. The guard covers the class rather than the one flag:
`TestEveryRemovedFlagIsRefusedByNameAndNeverSwallowsItsValue` in `cmd/krewe/removed_test.go` drives
every entry of `removedFlags` and refuses each one by name. Two scenarios drive a refusal through
its own process and assert the command fails, in `features/job.feature` and `features/taskword.feature`.

**446, a cost rule in prose is advice.** The third and strongest of the issue's three fixes is built.
`krewe job ask` puts a question on the record and nothing but an answer moves the job, at
`internal/job/job.go:38` and `features/asking.feature`.
`roles/orchestrator/ROLE.md` tells the orchestrator to ask before it declares the children that
build anything that bills. Each resource goes on its own line, with its cost at zero traffic beside
it. `features/plan.feature` holds the neighbouring gate: a person approves the plan before any work
starts.

Nobody ran a model against the brief, so what proves this is the mechanism and the brief,
not an observed run.

## Left open

Each line names one criterion the issue states and `main` does not meet.

**348, nothing measures the machine.** There is no node exporter in `deploy/docker-compose.yml` and
no processor unit metric anywhere. `docs/OBSERVABILITY.md:58` says the same on `main`. The second of
the three bullets is now readable through `internal/headroom`, which is what closes 405.

**354, a sub task runs as a named role.** "An event starts a task of a flow that declares
`on: { event: ... }`" is not met. Nothing can raise a trigger, so no graph that reacts ever starts.
See 433. Slices 1 and 2 shipped, in `features/roles.feature` and `features/rolesessions.feature`.

**363, a secret can be set and never taken away.** There is no `DeleteSecret` call and no
`krewe secret unset`. `krewe secret unmount GH_TOKEN` still answers with the usage of `set`, which
is the exact sentence the issue quotes.

**371, a session cannot start a container.** `krewe container` is an unknown command, and no control
plane call starts a container for a session.

**381, core services share one memory pool with the sandboxes.** "A sandbox carries a memory limit,
set by default" is not met. `QC_SANDBOX_MEMORY` is unset at `deploy/docker-compose.yml:112`, and
`cmd/controlplane/main.go:119` warns when it is, so a sandbox carries no limit unless an operator
names a figure.

**388, a task scatters its context across the workspace root.** `skills/git/SKILL.md` states a
layout, and it is a different one: `/home/agent/shared/repos/<name>` and
`/home/agent/shared/worktrees/$QC_SESSION_ID/<name>`. Nothing writes a `STATE.md` before the work
starts, and nothing separates what may be deleted from what must not be. The working rules live
outside this repository and were not read.

**394, a message names the handle the listing does not print.** The listing prints the id, at
`internal/display/session.go:32`. Five refusals still name the handle:
`internal/controlplane/server.go:1315` and `:2292`, `internal/controlplane/stoptask.go:152`,
`internal/controlplane/lifecycle.go:35`, and `internal/job/stall.go:133`. Nothing strips the
`rpc error: code =` prefix either.

**396, a session with no name shows an empty column.** The inference is built, and it moves. A
session is described again every ten tasks, at `describeEveryDefault` in
`internal/controlplane/describe.go`, and the issue asks for a name that lands once and then holds.

Everything else it wants is on `main`. `TestDescribingNeverOverwritesTheNameYouChose` proves the
name a person typed survives. `SessionLabel` falls back from the label to the title to the
description. This one is a judgement about the cadence, and the owner may read it the other way.

**397, an upgrade takes every running session away.** The first half is built:
`features/version.feature` and `reportDrift` say how far behind the stack is. The second is not.
`features/sessions.feature:66` states on `main` that a task cannot be dispatched after a restart,
and no scenario dispatches one.

**399, a trigger node so a run can start because something happened.** Slice 3 is not built. Nothing
writes a trigger row. Slices 1 and 2 are: the node type, the `pending_triggers` table at
`internal/store/migrations/0035_pending_triggers.up.sql`, and a dispatch that lets go and advances
on `task.finished`.

**401, secret files are mounted where nothing tells a session to look.** Nothing points a session at
`/run/secrets`. `taskEnv` sets no variable naming the directory. `skills/git/SKILL.md` still says authentication is
handled and names only GH_TOKEN from the environment. The issue says that sentence sends a session
the wrong way.

**418, two migrations can take the same number.** There is no guard. `internal/store` holds
`memory_test.go`, `order_test.go` and `pullrequest_test.go`, and none of them parses a migration
number. Two colliding pairs are on `main` now, `0007` and `0026`.

**422, four nouns for two ideas.** Nothing leads with the two questions. `krewe help` still prints
the commands as peers. The `work` noun became `job`, so the count is unchanged.

The manual's own
word list now defines `session` twice, with two different meanings, at
`internal/manual/manual.go`. The issue's test needs a person who never saw the tool before. Nobody ran that test.

**433, a trigger node cannot be fired.** The measurement in the issue still holds.
`grep -rn "Raise(" --exclude="*_test.go" .` returns one line, the definition at
`internal/flow/trigger.go:91`. There is no command and no ingress.

**438, the configuration should be a file the system reads.** `krewe diff` and `krewe apply` are
both unknown commands.

**450, the operator had to ship the work.** The first of the two fixes landed: 449 is closed, and
`features/publishing.feature` pushes a job's branch without asking anybody. The second did not. A
run that creates a repository has no standing permission to ship into it, decided at setup. Nothing
on `main` creates a repository at all. This one is a judgement about a case that cannot yet
arise, and the owner may read it the other way.

## Could not tell

None. All twenty were settled from the code, the tests and the commands.

## Two issues that overlap

399 and 433 are left open together, because merging them is the owner's decision and not this
document's. What is left of 399 is its slice 3, an ingress that writes a trigger row, and that is
the whole of 433. The two do not fully overlap: 399 also carries the node type and the non blocking
dispatch, and both of those shipped.
