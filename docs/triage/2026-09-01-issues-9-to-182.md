# Twenty open issues read against main, 1 September 2026

Twenty issues were read against the code on `main` at `d508eec`. The question for each one was not
whether somebody worked on it. It was whether the behaviour the issue asks for is in `main` today.

None of the twenty was closed. Every one of them states a criterion that the code does not meet.

## How each one was read

Each issue was read whole, with its acceptance criteria and its comments. Then the code, the
scenarios and the manual were searched for the behaviour. A commit subject and an issue reference
were treated as a claim, not as evidence.

No commit on `main` names any of these twenty issues, so nothing here rests on a commit message.

Where an issue names a command, the command was run. The tool was built from `d508eec` with
`go build ./cmd/krewe`, and these four answers are quoted from that binary:

```
$ krewe update
krewe: unknown command "update"

$ krewe skill approve foo
krewe: usage: krewe skill <import|list|attach|detach>

$ krewe session stop x
krewe: usage: krewe sessions [<address>]

$ krewe version
tool           dev
system         unknown
sandbox image  unknown
```

## Left open

Each line names one criterion the issue states and `main` does not meet.

**9, first chat channel inbound.** No channel writes to the event log. `internal/channel` holds the
contract and an in memory double, and `cmd/gateway/main.go` boots telemetry and waits.
`docs/EVENTS.md` line 36 says the same thing.

**10, gated outbound delivery.** No channel delivers a reply. The only `Deliver` on `main` is
`MemoryAdapter.Deliver` in `internal/channel/channel.go`, which appends to a slice.

**11, second chat channel.** There is no first one to be additive to. No adapter for any chat
provider exists.

**15, sandbox tiers and permission tiers.** `sandbox.ResolveKind` accepts `docker` and `local` only,
so there is no ssh tier. The `Channel` message in `proto/quaycrew/v1/controlplane.proto` line 16
carries a workspace, an id and a kind, so a channel caps nothing its sessions may do.

**20, cloud implementations behind the interfaces.** `go.mod` names no cloud software development
kit. The store is Postgres or memory, secrets are Postgres, and the sandbox is Docker or local.
Nothing is selected by configuration because nothing exists to select.

**21, deploy to the cloud through CI on merge.** `.github/workflows/` holds one file, `ci.yml`, and
its jobs are unit, integration, containers, promises and secrets. No job deploys anything.

**22, reviewed learning loop.** Nothing drafts a hook, a skill or a rule from a finished session.
The only propose on `main` is `ProposeJobPlan` in `internal/store/store.go` line 429, which is a job
putting its own plan to a person.

**24, voice input via local transcription.** Nothing in the repository reads audio.

**36, session commands in the command line tool.** `krewe stop` calls `StopTask`
(`cmd/krewe/stop.go` line 42), which stops the task and keeps the session. `StopSession`,
`RestartSession`, `ArchiveSession` and `RestoreSession` are reached from the console only.

**45, read surface for the console.** `StreamTasks`, `ListStreams` and `ListMetrics` are not on
`ControlPlaneService`, and the `Session` message carries no `sandbox_id`. `GetHeadroom` answers part
of what `ListSandboxes` was for, and it carries neither the image nor the age.

**46, run the whole stack on Kubernetes.** There is no manifest, no kustomize overlay and no chart.
The only Kubernetes in the repository is prose comparing this design to that one.

**47, Kubernetes sandbox provider.** There is no `KubernetesProvider`. `sandbox.NewProvider` returns
`LocalProvider` or `DockerProvider` and refuses every other kind.

**74, versioning and an update command.** `quay version` shipped, and it ran here. `krewe update` is
not a command, and `.github/workflows/` publishes no release, so neither half of the update comes
from anywhere.

**78, the console's view set.** The console registers eleven views: jobs, workspaces, projects,
context, secrets, sessions, tasks, archived, stats, room and keys. The map still wants an events
view, an observability view, a flows view, the tree, the pulse, error zoom, the narrow and wide
toggle, a filter grammar and prompt hotkeys.

**85, parity with the sessions tool.** `Resource.SortBy` is one fixed column each resource declares
(`internal/console/resource.go` line 189), so `s` does not cycle the sort. `s` is the alias for the
sessions view. Nothing records the branch a session works on, so no view shows one.

**88, a state engine.** There is one way to keep state: `sandbox.Storage`, a bind mount of a host
directory. `GetInfo` reports where state is configured to live and never verifies that a sandbox
has it, which is the failure the issue names.

**92, switch the current workspace from the console.** The workspaces view declares no actions
(`internal/console/resources.go` line 23). The file at `~/.krewe/context` is written by
`cmd/krewe/context.go` line 54 and by nothing in the console.

**94, Claude's own numbers in the console.** The sessions view has no task count column
(`internal/console/resources.go` line 305), and nothing in the system reads the plan usage limits.

**179, skills.** The loader, the git skill, the github skill and the signing key all shipped, and
`features/skills.feature` proves them. Two criteria are not met. A proposed skill cannot be
approved, because `krewe skill` takes import, list, attach and detach and nothing else. A project
that names a repository does not get a checkout of it on the first task: `krewe project repository`
records where the work lands, and the clone happens in conversation.

**182, flows.** The reducer, the graph, the wait, the ask, the schedule, the trigger node, the
transition cap, the token ceiling, the stop with a reason, the version pinning and the idempotent
dispatch on run, node and attempt all shipped. Webhook triggers did not.
`features/triggers.feature` line 13 says nothing outside the process can raise a trigger, so no
signature is checked and no allowlist of graphs exists.
