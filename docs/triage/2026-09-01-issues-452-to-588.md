# Twenty open issues read against main, 1 September 2026

Twenty issues were read against the code on `main` at `d508eec`. The question for each one was not
whether somebody worked on it. It was whether the behaviour the issue asks for is in `main` today.

Seven of the twenty were closed. Thirteen stay open.

## How each one was read

Each issue was read whole, with its acceptance criteria. Then the code, the tests and the scenarios
on `main` were searched for the behaviour. A commit subject and an issue reference were treated as a
claim, not as evidence. Ten of the twenty carry a merged commit that names them, and three of those
ten are still open.

Where an issue names a command, the command was run. The tool was built from `d508eec` with
`go build ./cmd/krewe`.

The suites were run at that commit. `go test ./features/` reports 996 scenarios, 987 passed and 9
failed. All nine failures are the install scenarios, which call `make`, and this sandbox holds no
`make`. `go test ./internal/... ./cmd/...` is green. The `deploy` package fails for the same reason.

Nobody drove a live control plane, so no criterion that needs a model, a token or a running system
was settled by observation. Where that limited an answer, the line below says so.

## Closed

Each line names what proves the behaviour is on `main`.

**507, the Makefile guards a directory that no longer exists.** The `Makefile` holds no `home-check`
target, and `up`, `upgrade` and `install` call nothing in its place.

**513, nothing reviews a pull request.** `flows/pull-request-review.yaml`, with
`internal/flow/pullrequestreview_test.go`, `internal/flow/pullrequestreviewrun_test.go` and
`features/pullrequestreview.feature`. Fourteen tests pass by name. The scenarios cover the stop, the
answer of no, the answer of yes and a run that finds nothing. Nobody drove the graph against a live
pull request, because that needs a model and a token.

**519, infrastructure the deploy identity could never create.** `skills/deploy-identity/SKILL.md`,
seeded to the system at `internal/controlplane/seed.go`, and the `deploy-identity-gate` hook seeded
at `internal/controlplane/seed_hooks.go`. `features/deployidentity.feature` and
`features/deployidentitygate.feature` cover the four criteria, including the refusal of a denied
action.

**520, a run builds the document it was given.** `theFirstUsableStop` in
`internal/flow/advance.go`, with `features/product.feature`. The scenario for an answer of no is
there, and it is the answer the feature exists for.

**529, a failed job starts again from nothing.** `krewe job resume` and `krewe job refuse` in
`cmd/krewe/job.go`, with `features/resuming.feature`. Ten scenarios cover the five criteria,
including the refusal and the same step twice.

**533, the verifier and a green check.** `roles/verifier/ROLE.md` at version 3, under the ceiling,
with `internal/role/verificationgap_test.go` and `features/verificationgap.feature`.

**550, the briefing and a phone.** The decision is recorded in `docs/ARCHITECTURE.md`, beside the
sentence it changes. It chose the chat channel. Issues 9 and 10 carry that road, and both are open.

## Left open

Each line names one criterion the issue states and `main` does not meet.

**452, a role is a loose directory.** A project still cannot declare a roles directory that the
system imports from. `docs/ROLES.md` says so itself, under "What is not built". Where a role came
from is recorded and printed, which is visibility rather than review.

**468, the crew took the container runtime down with it.** The correction on the issue asks for two
things. Nothing reconciles a job against its session when the session dies, and nothing lists what
is recoverable.

**474, no console view of flows, roles, skills or hooks.** `NewDefaultRegistry` in
`internal/console/console.go` registers sessions, jobs, tasks, archived, projects, workspaces,
contexts, secrets, stats, room and keys. It registers none of the four.

**477, a sandbox has no limit.** `internal/sandbox/docker.go` passes one provider wide `--memory`
and no `--cpus`, and no limit comes from what the sandbox declared. The package comment in
`internal/capacity/capacity.go` says the limit is issue 477 and is not built.

**478, nothing evicts.** The same package comment says nothing evicts, and names this issue.

**506, the word above every workspace is system.** Piece one landed. Piece two did not: the compose
project, the container prefix, the protocol package and the sandbox image all still read `quaycrew`,
in 339 files.

**551, work the crew knows cannot run.** `CreateJob` gives no answer where the depth limit is zero.
`krewe context set` prints no size before the write, names no replacement, offers no spelling for
appending, and asks nothing back for the system level. It does refuse an empty input over content,
which is one criterion of nine.

**552, fifteen concepts before a product.** `guidedSetup` in `internal/console/wizard.go` still
chains workspace, project, secret, context, skill and session, so it ends in a message and asks for
no repository. Roles are not seeded: `SeedToSystem` holds skills only. `krewe help` opens on the
commands and names no four words. `krewe manual` still defines the word session twice.

**553, a job going the wrong way.** `RecordSteer` in `internal/controlplane/steer.go` writes the
mark and dispatches nothing. It refuses no phase, so a steer of a finished job still reads as
delivered.

**580, nothing lists what a plan assumes.** The `Job` message carries no assumptions, and there is
no `krewe job assume`. The claim rows in `internal/job/claim.go` are a hold on a piece of work,
which is a different thing.

**585, fabric and blueprint.** Nobody ran the two register searches, and `docs/NAME.md` says so
itself. No test reads `docs/NAME.md` against the name that `cmd/` builds, which the issue asks for
by name.

**586, one role reads the plan.** A run keeps one `result.reply` key and no `reply.<node>` key. A
job carries no questions, and `flows/` holds three graphs and no `plan-reading.yaml`.

**588, a fact a run discovers dies in its transcript.** There is no `krewe job found`, no verdict on
a claim row, and nothing in the shipped code calls `flow.Engine.Raise`.
