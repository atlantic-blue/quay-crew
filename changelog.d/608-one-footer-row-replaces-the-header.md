**The console says where you are on one footer row, and the header is gone.** The header was three
rows across the top of every window. It carried a wordmark in block letters, one build string and one
memory figure. Those three rows are rows of the listing now.

Under the list there is one row. Its left is where you are standing, written the way you would type
it, and how to leave: `acme/house-bills <jobs>   esc to go back`. Its right is what the header
carried, in the terminal's own green: `Version: b8712fa | <?> Help | Krewe`.

One row cannot wrap, so the right half gives way rather than being cut. Krewe goes first, then the
help key, then the build. The left half is drawn whole before any of it, because a person who cannot
see where they are has to guess, and a person who cannot see the build reads it in the help panel.

A control plane older than this tool takes the whole right of the row instead. It cannot say what it
is running, so every other thing that row could carry is blank, and the one thing worth saying is
`run make upgrade`.

The panel is two panes now, the console and the conversation, each the full height of the window.
The header pane went, and with it the hooks that held it to its own line count and the hook that
bounced the keyboard off it.

`krewe header` is refused by name. It says the build and the help key are on the console's footer
row, and that `krewe room` answers what the machine has left, which is the one thing the header
carried that the footer does not.

The console writes down where it was standing and opens there next time. A workspace or a project
that was removed since is not an error: the walk back down stops at the last level still there. A
console that has nothing written down opens at the top.
