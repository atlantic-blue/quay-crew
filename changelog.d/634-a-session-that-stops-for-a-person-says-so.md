**A session that stops for a person now says so on the record.** Four jobs stopped for a person on
the afternoon of 1 September 2026. Every conversation held a question. `krewe job list` read running
for all four and so did `krewe sessions`, none was asking, and nothing told anybody. The only way to
find out was to open each of the four conversations and read them, and while nobody did, nothing
moved.

Reproduced against a live control plane, the record had one road to "a person is needed" and it was
`krewe job ask`, which the session has to remember to call. Every other way a session stops for a
person read as something else. A question in prose ended the job as stopped, because the answer
stated no outcome. An answer stating `Outcome: decide`, which is the word the system offers for
exactly this, ended the job as done.

So the word is read. Three of the four say what became of the work. The fourth says the work stopped
with a person, and that one now puts the job in `asking` with what the session wrote under the line
as the question. It is the same phase, the same column and the same store call `krewe job ask`
already writes, so everything that reads what waits on you finds both roads and nothing has to learn
a second field. The answer goes back into the conversation that stopped, the way an answer to a
question always has.

It reads the answer rather than trusting a call, the way the pull request address and the outcome
already are. The session still has to state one of the four words, and the system already refuses to
settle a job whose answer states none, so the word is compulsory rather than remembered.

What this does not fix: a session whose task never ends. The job and the session both read running
for as long as a task is in flight, and nothing measures whether anything is happening inside it.
That is a separate cause with a separate fix, and it is not in here.
