**A merge is refused, and the crew is what refuses it.** Every role brief in this crew ends a slice
the same way: commit, push the branch, open a pull request, and never merge. A push applies nothing.
A merge runs the pipeline, and the pipeline spends money and changes infrastructure, so the merge is
the operator's gate. The crew could not say that. `may` grants the verbs a session calls on the crew,
and merging is a github action a session takes with a credential a skill gave it, so the control
plane never sees it. The one boundary the whole shape rests on was a sentence in a brief, while
smaller boundaries were held by a credential.

`merge-gate` is a hook, so the check happens inside the sandbox at the moment the command is about to
run. It refuses `gh pr merge` in every spelling, the same merge over `gh api`, `curl` and `wget`, the
`mergePullRequest` mutation, and a `git push` onto `main` or `master`, because landing a commit on
the branch a pull request merges into runs the same pipeline. It reads the command the way a shell
would rather than matching text, so `git commit -m "merge the two lists"` goes through: a hook that
refuses wrongly blocks the work, and every role pushes on every slice.

A fresh crew is put under it. That changes what a seeded hook meant, which was a hook that cannot
refuse. The rule now is that a seeded hook refuses something no session is ever meant to do, exactly,
and says what to do instead. `quay hook detach crew merge-gate` is how an operator decides otherwise,
and that is the honest shape of it: the boundary is a thing the crew holds and a person can remove
deliberately, rather than a sentence a model may or may not keep.

What it does not hold: a default branch called something other than `main` or `master`, and a merge
from a tool that is not Bash.
